\sect{Summary: The Drawdown Report}
Software engineer and cloud architect with 19+ years of hands-on experience (12+ as a freelancer), specializing in enterprise
modernization and cloud-native transformation. Currently IT architect at Union Investment (since April 2026), hands-on in the team behind
the public financial calculators. In parallel I run BitterQuant, a private ML research project on systematic trading on AWS.
Before that: Cloud Architect for LBBW's ``Phoenix'' IT modernization.

Most CVs show a straight line upward. Mine looks more like a stock chart: mostly up, with a few well-documented drawdowns.
This Anti-CV is the drawdown report: wrong technology picks, a leadership role I was not ready for, middleware that should not have existed,
and tools I still side-eye. Everything below is true; the humor is the only part I embellished.
I now work agent-first: coding agents write most of the code, and I keep architecture, scope and the go/no-go.
So far the agents have not asked to take credit for the failures. I am keeping those.

\sect{Recent Roles: Where the Lessons Are Freshest}

\role{Cloud Architect}{Landesbank Baden-W\"urttemberg (LBBW)}{Nov 2024 -- Dec 2025}%
{``Phoenix'' IT modernization (${\sim}$80 people), migration to the Azure-based ``Skywalker'' platform | 9-person team, remote}
\begin{itemize}
\item \textbf{Scope:} IT-architecture responsibility for 10 of 30 applications in the ``04 -- Application Development'' area. Assessed hundreds of legacy applications (Spring Boot, Tomcat, IIS) with the R-methodology.
\item \fail{Plot twist:} Skywalker was unused in production during my engagement. My platform gap analysis was a dress rehearsal with no audience: the cheapest time to find gaps, the loneliest time to present them.
\item \textbf{Output:} Solution Design Templates for FirstMovers, standardized assessment processes, and presentations to business and IT committees, where architecture goes to be voted on.
\item \fail{Tooling:} Jira, Confluence, Outlook, Citrix, Webex and draw.io: six windows open before the first box was drawn. Also evaluated Elastisys Welkin as an alternative platform. Azure Calculator estimates stay optimistic until the first invoice.
\end{itemize}

\role{IT Architect \& Platform Engineer}{Union Investment, second tour}{Apr 2026 -- present}%
{Architect for three teams of the funds squad; hands-on in Team Rechner (15+ public financial calculators) | part-time, remote}
\begin{itemize}
\item \fail{Inherited surprises:} Renovate had been intermittently broken for months. Reported backend coverage was 34\% until I fixed the measurement (real: 87\%). Scheduled API tests failed ``orange'' instead of red, so nobody was alerted. My best coverage jump needed zero new tests.
\item \textbf{Debt paydown:} Playwright retries cut from 3 to 0 so flaky tests surface instead of hiding. In a sibling team's monorepo I fixed 1,065 hidden type errors and cut the CI cache step from ${\sim}$8 min to ${\sim}$12 s.
\item \textbf{Boring on purpose:} Took over a conversational platform from an external agency into production in ${\sim}$4 weeks by reusing the existing monorepo pipelines. The winning move was refusing to add a runtime. The request-origin tracing stories had to ship in strict order, or the CORS preflight would have blocked every backend call. I wrote that down very clearly.
\item \fail{Open item:} A pen-test TLS finding could not be fixed directly (Azure Static Web Apps cipher suites are platform-managed). Solution: switch on the managed edge, i.e.\ pay someone else to own the problem.
\end{itemize}

\role{Software Lead \& Cloud Architect}{Union Investment}{Oct 2021 -- Dec 2024}%
{InvestmentWelt B2B portal: Liferay/FirstSpirit monolith $\rightarrow$ Self-contained Systems, teams of 5--7 | remote}
\begin{itemize}
\item \textbf{Built:} Microfrontend toolkit (Web Components), Java SDK for Azure Event Hubs, cross-system search (Algolia chosen over ElasticSearch), 1,000+ tests in a 10-minute build. Go-live December 2023, urgent deployments from days to 30 minutes.
\item \fail{Decision by shortcut:} After one PoC I went straight to Web Components without exploring alternatives, saving ${\sim}$60 person-days. The search architecture ``seemed impossible'' until a plain Pub/Sub on Event Hubs solved it. I overthink; the simple answer was waiting.
\item \fail{People part:} I had to remove team members who did not fit despite integration attempts. Necessary, not enjoyable. In 360\textdegree{} feedback, technical skill scored 9--10/10 in 2024, but I should explain more slowly to non-technical stakeholders and be more open to critical feedback. Both remain on my personal backlog.
\end{itemize}

\role{Middleware Engineer (sole developer)}{Saloodo! (DHL Group)}{Dec 2021 -- Nov 2024}%
{Golang middleware syncing platform data to Salesforce (${\sim}$10 million records) | part-time, remote}
\begin{itemize}
\item \textbf{Did:} Architected, coded, tested and operated it alone: fault-tolerant, stateless loop, 70\% coverage on 2,776 lines (5-second test run), SELECT times down by up to 80\% via SQL \texttt{EXPLAIN}. Also my ticket to professional Go.
\item \fail{Hindsight:} The middleware was architecturally unnecessary. Saloodo!'s core ran on AWS, so eventing plus Lambda would have been cheaper, simpler and faster. I built a very reliable answer to a question nobody needed to ask.
\item \fail{Garbage in:} The source database held wrong types and malformed JSON, so my tidy middleware had to tolerate other people's data.
\end{itemize}

\role{Senior Software Engineer}{Trusted Shops}{Aug 2018 -- Oct 2019}%
{JavaEE6 monolith $\rightarrow$ AWS; Salesforce/Zuora integration; Subscription team, then MARS unit | Cologne}
\begin{itemize}
\item \textbf{Built:} Upgrade Center, Salesforce/Zuora integration, serverless on Lambda/API Gateway/SQS with Terraform, Twilio SMS delivery, a Micronaut Lambda template. Contributed to 13+ repositories and ran Pact workshops.
\item \fail{Microservices, lived:} My first real microservices landscape. Simple changes touched many services, tests and automation were thin, and the architecture was not open to change. Skeptical of microservices as an overarching architecture ever since; I prefer Self-contained Systems.
\end{itemize}

\sect{Lessons That Stuck}
\begin{itemize}
\item \textbf{Quality is a speed feature:} As the sole developer at Saloodo!, tests and automation paid for themselves quickly. Technical debt paydown produced most of my 2026 numbers.
\item \textbf{Simple beats clever:} Pub/Sub on Event Hubs beat the ``impossible'' search architecture. Not knowing what works (BitterQuant) is an insight, too.
\item \textbf{You build it, you run it:} Every operations handover costs communication effort and mixes different working styles and assumptions.
\item \textbf{Familiar is not a strategy:} See Sphinx. Conversely, skepticism of Kubernetes and microservices has aged well so far, which is unfair to the other side.
\end{itemize}
