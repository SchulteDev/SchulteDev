\cvsection{Summary}
Software engineer and cloud architect with 19+ years of hands-on experience, 12+ of them as a freelancer. My regular CV talks about platforms serving 9M+ users, 99.9\% uptime and deployments cut from days to minutes. This one covers the other side: the decisions I would make differently, the technologies that humbled me, and the lessons that cost more than a conference ticket. Currently back at Union Investment as IT architect for three teams of the funds squad. In parallel I run BitterQuant, a private ML research project on systematic trading that has been paper trading since May 2026 \textendash{} the only kind of trading where my mistakes are free.

I work agent-first: coding agents write most of the code under my supervision, while I keep architecture, scope and quality decisions \textendash{} and therefore the blame. If there is one thread through this document, it is that engineering best practices still apply, no matter how good the tools get. Even the best model is still ``garbage in, garbage out''.

\cvsection{Key Impacts (of the Other Kind)}
\begin{cvkpis}
\kpi{100\%}{uptime of a middleware that did not need to exist}
\kpi{11 yrs}{from first trading bot to (still) paper trading}
\kpi{2}{promising strategies killed by a realistic simulator}
\kpi{8 yrs}{for one Diplom, working alongside}
\kpi{1,065}{hidden type errors in a single monorepo}
\end{cvkpis}
\begin{itemize}
  \item \textbf{Leadership by assumption:} Became Head of Development in 2008 without management experience. The company and I both assumed technical skill would translate into leadership. It did not, at least not automatically.
  \item \textbf{Familiar beats better, briefly:} Chose Sphinx over ElasticSearch because I knew it. ElasticSearch's ``exotic'' features became the industry standard, and the platform migrated to it later anyway.
  \item \textbf{Microservices reality check:} My first real microservices architecture in 2018 taught me that simple changes can ripple through many services. Since then I have preferred Self-contained Systems.
  \item \textbf{Kubernetes and I:} We met in 2017 and never fully reconciled. In my view it is a tool for IT operations providers, not for running a single simple application.
  \item \textbf{Architecturally unnecessary, operationally flawless:} Kept a Golang middleware at 100\% uptime for three years. In hindsight, an integrated AWS Lambda solution could have been cheaper, simpler and more robust.
  \item \textbf{Not every lesson hurts:} Going straight to Web Components after one PoC, without exploring other integration paths, saved about 60 person-days. Sometimes bias for action beats a comprehensive option analysis.
  \item \textbf{Hard calls:} Building teams included removing members who did not fit despite integration attempts. Team composition decides projects, and avoiding that decision only postpones it.
\end{itemize}

\cvsection{Recent Roles: The Uncut Version}

\cvrole{IT Architect \& Platform Engineer \textbar{} Union Investment}{Apr 2026 -- present}{Freelance, part-time, remote \textbar{} architect for three teams, hands-on in Team Rechner (15+ public financial calculators)}
\begin{itemize}
  \item Inherited a calculator monorepo where Renovate had been intermittently broken for months. After the fix, the median time-to-merge of dependency updates dropped from \textasciitilde{}2 h to 13 min. Bots need supervision too.
  \item Found that the backend reported 34\% line coverage while the real figure was 87\%, because generated code and non-Quarkus tests were miscounted. A rare case where the code was better than its dashboard.
  \item Cut automatic Playwright retries against deployed sites from 3 to 0, so flaky tests surface instead of hiding. Scheduled API tests used to fail silently in orange rather than red; now a failing run alerts.
  \item Could not fix a penetration-test TLS finding directly, because Azure Static Web Apps manages its cipher suites. Every handover to separate operations teams costs effort, which confirms my belief in ``you build it, you run it''.
\end{itemize}

\cvrole{Cloud Architect \textbar{} LBBW}{Nov 2024 -- Dec 2025}{Freelance, remote \textbar{} ``Phoenix'' IT modernization (\textasciitilde{}80 people), architectural responsibility for 10 of 30 applications}
\begin{itemize}
  \item Designed migration paths onto the Azure-based ``Skywalker'' platform, which had been in development since 2023 and was not used in production during my engagement. Architecture in its purest, most hypothetical form.
  \item Cataloged hundreds of legacy applications with the R-methodology. Their diverse stacks (Spring Boot, Tomcat, IIS, Oracle, MS-SQL) each demanded an individual migration approach rather than one neat template.
  \item Spent much of my energy finding platform gaps instead of shipping features, and evaluated Elastisys Welkin as an alternative for vendor flexibility. Finding what is missing is valuable, but less satisfying than building it.
  \item My daily toolchain was Jira, Confluence, draw.io, Outlook, Citrix and Webex, with notably fewer compilers than usual. A useful reminder of how much architecture is communication with committees.
\end{itemize}

\cvrole{Software Lead \& Cloud Architect \textbar{} Union Investment}{Oct 2021 -- Dec 2024}{Freelance, remote \textbar{} modernization of the B2B sales platform InvestmentWelt, teams of 5--7 developers}
\begin{itemize}
  \item Not the lead of the overall modernization: architectural responsibility lay with Union Investment. My part was proposing the microfrontend approach that was finally adopted, and then building the toolkit for it.
  \item Search across eight domains initially seemed impossible. The answer turned out to be plain publish/subscribe via Azure Event Hubs. I had overestimated the problem, not underestimated the architecture.
  \item 360\textdegree{} feedback rated my technical competence highly, but also asked me to slow down technical explanations for less technical stakeholders and to keep developing my openness to critical feedback.
  \item Learned that SCS, automation and Communities of Practice take extra effort but pay off in throughput and quality.
\end{itemize}

\cvrole{Middleware Engineer \textbar{} Saloodo! (DHL Group)}{Dec 2021 -- Nov 2024}{Freelance, part-time, remote \textbar{} sole engineer synchronizing \textasciitilde{}10 million records to Salesforce}
\begin{itemize}
  \item Took the gig mainly to finally use Golang professionally, then delivered 100\% uptime over three years for a component that, in hindsight, eventing plus AWS Lambda could have replaced.
  \item Wrote a lot of code to tolerate the upstream database: incorrect types and malformed JSON values. My error handling became considerably more robust than its inputs.
  \item As sole developer without team support, I learned that investing in quality (70\% coverage, 5-second test runs with Dockertest) quickly pays for itself, even for a team of one.
\end{itemize}

\cvrole{Senior Software Engineer \textbar{} Trusted Shops}{Aug 2018 -- Oct 2019}{Freelance, Cologne \textbar{} Subscription team and MARS unit, migration from a JavaEE6 monolith to AWS}
\begin{itemize}
  \item First encounter with a real microservices architecture: simple changes often required modifications across many services, and missing tests and automation made maintenance hard.
  \item The IT architecture was not open to change, so the lesson stayed with me rather than with the system. I have been skeptical of microservices as an overarching architecture ever since.
  \item Spread Pact contract testing across teams and built a reusable Micronaut AWS Lambda template. In other words, I fought distributed complexity with more tooling, which is the microservices way.
\end{itemize}

\cvsection{Personal Projects: Learning by Failing on Purpose}
\begin{itemize}
  \item \textbf{BitterQuant (since Jan 2026):} Fine-tuning time-series foundation models on intraday US-equity data, following Rich Sutton's ``Bitter Lesson''. Two promising approaches collapsed once execution was simulated realistically. The simulator turned out to be the most important part of a trading system, and documented null results now prevent repeated dead ends.
  \item \textbf{Crypto-arbitrage trading bot (2015):} My first attempt at automated trading, built with Weka and LibSVM. Eleven years later the interest is the same; only the models got bigger.
  \item \textbf{ConversationalAI4J (2025 -- 2026):} Voice conversations with local LLMs via Whisper.cpp, Piper and Ollama, and my first project coded by AI agents under my supervision. It is where I learned to review rather than type.
  \item \textbf{John review (since Jul 2026):} Labelling a pull request triggers a headless coding agent that reviews the change, pushes one fix commit per finding and posts a verdict. It encodes YAGNI and KISS, rules every engineer, myself included, benefits from being reminded of.
  \item \textbf{Sse-BelMngr-Hermine (since 2025):} Golang CLI using Azure Document Intelligence to capture tax documents. It gets small improvements once a year, exactly when the next tax return can no longer be postponed.
  \item \textbf{Smaller experiments:} A Python CLI to limit Deye microinverter output via Modbus (2026), multi-resolution time-series charts from static Parquet files without a backend (2026), and a Jenkins--GitHub integration PoC on Google Cloud and Firebase (2018).
