\cvsection{The Short Version (Read Before Hiring)}
Freelance cloud architect and software engineer who has made most mistakes at least once and wrote them down as lessons. Java is my mother tongue, Golang my preferred dialect, PHP the accent from my teens. Since 2025 coding agents write most of my code; I keep architecture, review and the go/no-go, and learned that even the best models still obey ``garbage in, garbage out''. My slogan is ``Crafting solutions that thrive today and tomorrow''; this document covers yesterday.

\cvsection{Key Impacts (Mostly on Myself)}
\begin{cvkpis}
\kpi{\textasciitilde 7 mo.}{onboarding at Saloodo before any coding}
\kpi{0}{production users on LBBW's Skywalker during my stay}
\kpi{1,065}{hidden type errors in a sibling team's repo}
\kpi{29.5\%}{line coverage of a 9M+ member platform (2014)}
\kpi{2}{trading ideas killed by realistic simulation}
\end{cvkpis}
\begin{itemize}
\item \textbf{Promoted past my experience:} Became Head of Development at werkenntwen in 2008; everyone, me included, assumed technical skill would turn into leadership. It did not, until training and reflection got me to a laissez-faire style that suits me and the team.
\item \textbf{Chose the familiar search engine:} Picked Sphinx over ElasticSearch, whose features looked exotic. In 2012 my colleagues migrated to ElasticSearch, the politest form of code review.
\item \textbf{Met Kubernetes in 2017:} Found it too complex for ops and developers alike to run a single application. Still do: a tool for operations platform providers, not for your one modest service.
\item \textbf{Skipped the option analysis:} Went straight to Web Components after one PoC, without exploring alternatives, and saved \textasciitilde 60 person-days. Not a method I can recommend, only one I can confirm.
\end{itemize}

\cvsection{Recent Roles, Without the Marketing}
\cvrole{IT Architect \& Platform Engineer \textbar{} Union Investment, the Sequel}{Apr 2026\textendash present}{Part-time freelance via percision services; architect for three teams, home in the team behind 15+ public financial calculators}
\begin{itemize}
\item Renovate had been intermittently broken for months; once fixed, the median merge time of dependency updates fell from \textasciitilde 2 h to 13 min. Bots, too, do better when someone reads their PRs.
\item The backend reported 34\% line coverage; fixing the measurement (generated code was miscounted) revealed 87\%. My biggest coverage win needed zero new tests. Scheduled API tests had failed silently in orange; now red means red.
\end{itemize}

\begin{itemize}
\item Catalogued hundreds of legacy applications (Spring Boot, Tomcat, IIS) with the R-methodology and turned the platform's missing features into a gap analysis, the enterprise word for a to-do list.
\item Evaluated Elastisys Welkin as an alternative and priced migrations with the Azure Calculator: every strategic platform needs a rival and a spreadsheet.
\end{itemize}

\cvrole{Middleware Engineer \textbar{} Saloodo! (DHL Group)}{Dec 2021\textendash Nov 2024}{Part-time freelance; sole developer of ``Salooforce'', syncing platform data to Salesforce; my first professional Golang}
\begin{itemize}
\item Rewrote the middleware as v3 because v2 had never gone live. After 77 releases and 100\% uptime, my own verdict: it was architecturally unnecessary; events and AWS Lambda would have been cheaper and simpler.
\item A full sync of six years of Quotes ran out of 12 GiB of memory, Salesforce answered parallel bulk loads with TooManyLockFailure, and the database added malformed JSON. Quotes went back to serial mode.
\end{itemize}

\cvrole{Software Lead \& Cloud Architect \textbar{} Union Investment}{Oct 2021\textendash Dec 2024}{Remote freelance; B2B portal InvestmentWelt (80,000 users) from a Liferay/FirstSpirit monolith to Self-contained Systems; teams of 5\textendash 7}
\begin{itemize}
\item The cross-domain search first seemed impossible; what worked was plain pub/sub over Azure Event Hubs. The complexity was optional; I just had not noticed yet.
\item 360\textdegree{} feedback rated my communication 3/5, the ideal value on a scale from too little to too much. Growth areas: slower explanations for non-technical stakeholders, more openness to critical feedback.
\end{itemize}

\cvrole{Senior Software Engineer \textbar{} Trusted Shops}{Aug 2018\textendash Oct 2019}{Cologne freelance; subscription and messaging services on AWS with Salesforce, Zuora and Twilio}
\begin{itemize}
\item First real microservices architecture: simple changes touched many services, tests were scarce, and the architecture was not open to change. I have preferred Self-contained Systems ever since.
\item Built a reusable Micronaut template for AWS Java Lambdas and taught Pact across teams, so services could agree in writing on what they expected from each other.
\end{itemize}
