\sect{Recent roles: where the lessons were most expensive}

\role{IT Architect \& Platform Engineer --- Union Investment}%
{Freelance via percision services GmbH, part-time, remote; ``Web Portals'' domain, second engagement}{Apr 2026 -- present}
\begin{itemize}
\item \win Architect for three teams, hands-on in Team Rechner (15+ public financial calculators as React apps and Web
Components, Quarkus backend). Unit tests 538 $\rightarrow$ 1,659, coverage gates from zero, per-branch previews, 4--7
team-run releases per month since July 2026.
\item \fail What I found: Renovate intermittently broken for months, backend coverage misreported (34\%; 87\% after fixing
the measurement), 1,065 hidden type errors in a sibling team's monorepo. I also cut automatic Playwright retries from 3
to 0, deliberately making CI redder so flaky tests stop hiding.
\item \twist A pen-test TLS finding could not be fixed directly (Azure Static Web Apps cipher suites are platform-managed),
so I switched on the managed edge instead of building my own. A conversational platform from an external agency went
to production in about 4 weeks by reusing our monorepo pipelines.
\item \les Most of my ``results'' are repaid technical debt, and my best work is invisible to end users. Separate ops teams
cost a handover per change; ``you build it, you run it'' remains my conviction.
\end{itemize}

{Freelance, part-time, remote, alongside Union Investment; sole developer}{Dec 2021 -- Nov 2024}

\sect{Earlier battles: the failures that built the character}

\role{PHP Developer, Head of Development, Backend Developer --- wer-kennt-wen}%
{Permanent position; social network with 9+ million members; acquired by RTL interactive in 2009; closed 30 June 2014}{Aug 2007 -- Jun 2014}
\begin{itemize}
\item \fail Head of Development (2008--2010) without management experience. The company and I both assumed technical
competence would translate into leadership. It did not; I had underestimated the human factor. Training and reflection led
me to a laissez-faire style that suited me and the team better.
\item \fail Chose the Sphinx search engine over ElasticSearch because I knew it, and ElasticSearch seemed exotic. ElasticSearch became
the industry standard and the platform later migrated to it while I was back as backend developer. Familiarity is not an
architecture criterion.
\item \win Moved procedural code to multi-layered object-oriented MVC; migrated groups and messaging to Zend Framework; built a
REST API (WADL) and mobile portal; table partitioning and Memcache for scale; Jenkins CI and PHPUnit; page loads $-$60\%.
\end{itemize}

\sect{Lessons greatest hits}
\begin{enumerate}
\item Familiarity is not an architecture criterion (Sphinx, 2008).
\item Technical competence does not automatically make a leader (Head of Development, 2008).
\item Before building middleware, ask whether an event and a Lambda would do (Saloodo!, 2021).
\item Fix the ruler before you celebrate the number: honest metrics beat flattering ones (coverage, test retries, 2026).
\item Not knowing what works is also a result; document the null results (BitterQuant).
\item Explain more slowly to non-technical stakeholders, and take critical feedback more openly (360$^\circ$ feedback).
\end{enumerate}
